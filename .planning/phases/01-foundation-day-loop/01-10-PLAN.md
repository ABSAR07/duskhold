   - If total is 0, do nothing: no "+0 gold" is shown.
   - Otherwise, for each spot in `per_spot` order and for each gold coin that spot pays:
     1. Compute the start point from `get_viewport().get_camera_3d().unproject_position(spot position + Vector3(0, 2.5, 0))`.
     2. Spawn a small TextureRect coin (radial `GradientTexture2D`, gold) there.
     3. Stagger coins 0.08 s apart.
     4. Tween each coin over 0.6 s to the centre of `%GoldLabel`'s global rect, with a small upward "pop" first.
     5. When a coin lands, free it and emit `coin_landed()`.
   - After the last coin lands, show `%PayoutTotal` ("+%d gold" % total) for 2.0 s.
   - Expose `live_coin_count() -> int` and `get_last_total() -> int`.

3. **`hud.gd`:**
   - On `dawn_payout`, set `_payout_pending = total`. On each `coin_landed`, decrement it by 1 (never below 0).
   - Displayed gold = `get_gold()` - `_pending` - `_payout_pending`. The counter visibly ticks up as coins land and finishes exactly at Economy gold.
   - The Economy has already been credited when DAWN began. This is display only.

4. **`tests/e2e/test_dawn_payout.gd`:**

   1. Parse `OS.get_cmdline_user_args()` for `--shot=<name>` (required) and `--out=<dir>` (default `res://screenshots`).
   2. If `DisplayServer.get_name() == "headless"`, print "screenshots need a real renderer; never run under --headless" to stderr and quit with code 2 (Pitfall 1 guard).
   3. Instantiate `prototype_map.tscn`. Before adding it, set `map_config` to a `prototype_map.tres` duplicate with starting_gold 30, so scenes can show several buildings. Add it as a child and await 3 frames.

   5. `await RenderingServer.frame_post_draw`, then take `get_viewport().get_texture().get_image()`.
   6. **Non-blank check:** resize a copy to 64×36, compute the luminance variance and count distinct colours quantized to 4 bits per channel. Fail (quit 1, nothing saved) when the variance is below 0.0005 or there are fewer than 8 distinct colours.
   7. Otherwise `save_png("<out>/<name>.png")` and quit 0.

2. **`tools/screenshot/shot_scenarios.gd`**: `class_name ShotScenarios extends RefCounted`, with `static func run(name: StringName, runner: Node, map_root: MapRoot) -> bool`. Every scenario drives the game through the real input actions or `ctx.commands` intents, never by setting simulation state directly:
   - `day_overview`: submit BuildIntent for house_1 and house_2 and upgrade house_1 once. Wait 0.8 s at spawn.
   - `spot_label`: teleport the king beside house_3. Wait 0.6 s so the label shows.
   - `build_in_progress`: teleport beside tower_1, press `action_build`, and capture after 2.5 coin intervals, while coins are mid-flight and the label is part-filled. Release afterwards.
   - `night_banner`: build 2 Houses, submit StartNightIntent, wait 1.3 s (night mood and banner).
   - `dawn_payout`: build 2 Houses, submit StartNightIntent, wait placeholder_night_seconds + 0.35 s (dawn light, coins flying).
   - `overlay_on`: press and release `toggle_debug_overlay`, then wait 0.6 s.

   The shot names are exactly these six.

3. **`tools/screenshot.sh`** (bash; Git Bash on Windows and bash on Linux CI). It sources `_common.sh`, then:
   1. Creates `screenshots/` (its tracked `.gdignore` keeps the PNGs out of the import scan).
   2. Runs the headless `--import` warm-up once. That is the only headless call.
   3. For each requested shot (default: all six), runs `timeout 120` with the pinned binary and the arguments `--path "$DUSKHOLD_ROOT_NATIVE" --resolution 1280x720 res://tools/screenshot/shot_runner.tscn -- --shot=<name> --out="$DUSKHOLD_ROOT_NATIVE/screenshots"`:
      - When `DUSKHOLD_SCREENSHOT_COMPAT=1`, it adds `--rendering-method gl_compatibility --rendering-driver opengl3` before the scene path.
      - On Linux with no `DISPLAY`, it wraps the command in `xvfb-run -a -s "-screen 0 1280x720x24"`.
   4. Exits non-zero if any run fails or its PNG is missing, and prints the saved file list.

4. **Run locally** on Windows with `bash tools/screenshot.sh` (real GPU, Forward+). Open each of the six PNGs with the Read tool and write a one-line description of what each shows in the SUMMARY. The PNGs are git-ignored and are never committed.

5. Run `bash tools/lint.sh`, which covers `tools/`. Commit the four files by explicit path.
