## Phase Goal

ROADMAP Goal (verbatim; not in user-story format, no story invented, flagged): "The king leads an army. The player builds a Barracks and an Archery Range whose squads fight on their own, commands them RTS-style with hotkeys, mouse selection and control groups, and fires the weapon's active ability. The keyboard-and-mouse command layer becomes the full Age of Empires style the owner asked for: the player sees each selected squad's patrol and queued orders on the ground, drags a box to select, and stores and recalls numbered control groups whose number shows on the squad's slot.

Output: patrol lines, numbered queued discs and hover preview; SelectionMath.squads_in_rect, the DragBox and drag handling; control groups in SelectionModel, the digit and modifier actions, badges, toasts and the recall flash; and their tests.
</objective>

## Scope rationale

files_modified lists 18 paths; the plan is kept whole on purpose (plan-checker scope_sanity warning, revision 1). Its three expansion tasks work on the same four input and presentation files (order markers, selection rings, selection controller, selection model) to finish the keyboard-and-mouse command layer: ground feedback, the drag box and control groups; six of the 18 paths are tests. `gsd-tools estimate-check --tokens 125000` reports 1.25x the 100k smart-zone budget; the check is advisory, never a block. Plans run one executor at a time on the main checkout, so the file count creates no parallel conflict; the binding limit is one executor's context, and Phase 2's 33-path plan 02-01 ran inside one executor (19 min, 02-01-SUMMARY). Splitting would renumber every later plan, whose actions cross-reference each other by number.

Re-slice if needed: should an executor run short of budget, the plan splits at the Task 2 / Task 3 boundary inside 03-08 (the executor stops after Task 2's commit and a fresh executor resumes at Task 3), so no later plan is renumbered. Slice 1 is Tasks 1-2: the ground feedback and the drag box, the pointer half that edits OrderMarkers, SelectionRings and SelectionController. Slice 2 is Task 3: the control groups, digit actions, badges and recall flash, built on SelectionModel and CommandKeyController with slice 1's committed SelectionRings.

## Flagged Assumptions

- Control-group semantics (RESEARCH A12, decided here for the UI-SPEC's unresolved row): groups hold squad ids, never drop a member at 0 alive, a new squad joins no group, recalling an empty group keeps the selection with a toast. The owner may ask for auto-join at the UAT.
- The store toast names the key digit, so storing on key 0 reads "Group 0 saved", matching the badge.
