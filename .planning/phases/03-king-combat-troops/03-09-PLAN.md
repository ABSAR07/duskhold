## Phase Goal

ROADMAP Goal (verbatim; not in user-story format, no story invented, flagged): "The king leads an army. The player builds a Barracks and an Archery Range whose squads fight on their own, commands them RTS-style with hotkeys, mouse selection and control groups, and fires the weapon's active ability. All of it is fully playable on keyboard and mouse or on gamepad with a complete in-run HUD."

<objective>
Everything the keyboard and mouse can command, the gamepad can too: D-pad verbs with an LB layer, cycling and type selection, a Start group mode for storing and recalling groups, and a right-stick ground cursor for move, attack-move and patrol, with a test that pins a path for every in-run capability on both devices.

Purpose: INPT-02's gamepad half and D-12, so a pad player reaches UNIT-09 and UNIT-10 without a pointer.

Output: the pad bindings and twins, PadChords, the group mode, GroundCursor and PadCursorController, the cursor view, zoom suppression, the capability test and the pad e2e tests.
</objective>

## Scope rationale

files_modified lists 18 paths; the plan is kept whole on purpose (plan-checker scope_sanity warning, revision 1). It is the gamepad half of the command layer the 03-06 to 03-08 plans built for keyboard and mouse: Task 1 the D-pad chords, LB layer and Start group mode, Task 2 the right-stick ground cursor that feeds the same intents; seven of the 18 paths are tests. `gsd-tools estimate-check --tokens 125000` reports 1.25x the 100k smart-zone budget; the check is advisory, never a block. Plans run one executor at a time on the main checkout, so the file count creates no parallel conflict; the binding limit is one executor's context, and Phase 2's 33-path plan 02-01 ran inside one executor (19 min, 02-01-SUMMARY). Splitting would renumber every later plan, whose actions cross-reference each other by number.

Re-slice if needed: should an executor run short of budget, the plan splits at the Task 1 / Task 2 boundary inside 03-09 (the executor stops after Task 1's commit and a fresh executor resumes at Task 2), so no later plan is renumbered. Slice 1 is Task 1: the pad bindings, PadChords, the Start group mode and the capability and select-one-type tests, which pass on their own because the point verbs' pad bindings land there. Slice 2 is Task 2: GroundCursor, PadCursorController, the cursor view and zoom suppression, which receive the point verbs that slice 1's CommandKeyController resolves.
