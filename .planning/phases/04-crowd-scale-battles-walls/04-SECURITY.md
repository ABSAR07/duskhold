## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Simulation -> presentation | Views read enemy, unit and arrow positions, ids and events every frame into MultiMesh batches; a write back would break replay identity | Positions, ids, attack and death events (read-only) |
| Simulation queries -> replay identity | A spatial query that answers differently from the shipped scan changes every later outcome | Nearest-structure and nearest-enemy answers, push-apart displacements |
| Map data (.tres) -> MapConfig.validate and the wall simulation | Untrusted geometry, tier data and run polylines drive allocations and per-tick loops | Wall runs, lengths, gaps, costs, tiers |
| Map data -> nav grid allocation | Content bounds and cell size size the grid and every flow field | Grid extents, cell counts |
| Data (health, damage, tunables) -> integer decision arithmetic | Large or malformed numbers could overflow or divide by zero in WallDecision | Health, damage per 10 s, ticks |
| CLI arguments -> stress tools (step bench, gate harness, stress night, frame report) | Untrusted strings size runs and choose output folders | Integers, output directories under res://build |
| Golden files -> CI verdicts | A regenerated golden can hide a regression | smoke, army, walls digests; full_idle unpinned by design |
| Local repo -> GitHub and CI runners | Pushed code runs in CI with the workflow's permissions | Source, workflow YAML, artifacts |
| Project -> Windows export | Tools, tests and the GUT addon must not ship | Export filter |
| Enemy data (.tres) -> target rule (04-12) | A def flag (`drops_blocked_targets`) selects which wall rule an enemy follows | One boolean per enemy def |
| Debug overlay -> simulation (04-13) | The F3 overlay reads the simulation and must never write it | Scene offsets only; rows are read-only providers |
| GitHub (godotengine/godot-cpp) -> .tools/godot-cpp -> shipped DLL (04-14) | Third-party C++ source is compiled into what ships; it is fetched by `tools/native_build.sh --fetch` into the git-ignored `.tools/` and never committed | One pinned commit SHA, godot-cpp sources, the API JSON dumped from the checksum-verified engine binary |
| Native code -> game process (04-14) | C++ runs in-process with no sandbox | Everything the facades hand to the extension; the extension opens no file, network, input or scene surface |
| Compiler flags -> replay determinism (04-14) | A build switch can change float results and with them every golden digest | Compile switches in `native/CMakeLists.txt` and `compile_commands.json` |
| Built library -> every Godot run (04-22) | A stale or missing library would test or ship old code | `addons/duskhold_sim/bin/` library and source stamp |
| GDScript facades -> native stores (04-15 to 04-20, 04-23) | Packed arrays, ids, spot and segment indices, cell indices, def indices and reaches cross into NativeSim, NativeWalls, NativeField and NativeGrid, NativeStructures, NativeWallDecision, NativeEnemies and NativeStuck; two copies of state (segment health, grid masks, enemy records) must never disagree | Arrays, integers and floats from GDScript |
| CI job -> CI job (artifacts) and CI artifact -> shipped build (04-16) | A library built in one job is loaded by the test, screenshots and export jobs, and the export packs the DLL players download | `native-linux` and `native-windows` artifacts of the same run |
| Trace and attribution CLI arguments -> files (04-20, 04-23) | Tools-only CLIs write `.txt` files | Allowlisted integers and a path under `res://build` |
| Measurement -> owner decision (04-21) | The frame report decides whether PLAT-01 is met | Frame times against the 8.0 ms budget |
| Build output -> installed library (04-24) | What the wrappers, the tests and the export trust as the native code is the file in `addons/duskhold_sim/bin/` and the stamp beside it; a failed or locked copy must never leave a valid-looking pair | The built library, its source stamp and its sha256 (`duskhold_native_install`, `duskhold_require_native`) |
| CI job -> CI job, the stamp (04-24) | The library travels between jobs with its stamp, and every job recomputes the same two lines | `addons/duskhold_sim/bin/` of the `native-linux` and `native-windows` artifacts of the same run |
| Command line -> the two view instruments (04-24) | `view_fill_bench.gd` and `view_ablation.gd` are tools-only; untrusted strings size the runs and name an output folder | Allowlisted view names, bounded integers, a duration in whole 30 s trials, a folder under `res://build` |
| GDScript -> the native view fills (04-25 to 04-27) | `NativeArrows`, `NativeEnemyViews`, `NativePuffs` and `NativeUnitViews` write the batch mirrors every frame from packed arrays, ids, slots, batch indices and layouts that GDScript hands over; the fills must read the simulation and never write it | Packed read views, mirrors and layouts, hit times and clock values as arguments |
| UnitSystem -> UnitReadView -> native fill (04-27) | A read path into the simulation that must stay read-only and must not change replay identity | One packed copy with a change counter |
