<exact_port_rules>
Restated in every view-port plan (04-25 to 04-27), adapted from the simulation port's rules (04-15 to 04-23):
1. Vector2 and Vector3 are godot-cpp types with real_t float (precision single); Color components are float; PackedFloat32Array elements are float. Every GDScript float (constants, delta, blend, t, frame-clock arithmetic, a method result once it leaves the method, PackedFloat64Array elements) is double in C++; GDScript int is int64_t.
2. Narrow exactly where GDScript narrows: a scalar meeting a vector at an operator or as a lerp weight is cast to real_t there; a store into a PackedFloat32Array (`_elapsed[slot] += delta` reads a float, adds in double, stores a float), a Vector3 or a Color built from doubles narrows each component; a vector length or distance is widened to double as it leaves. Keep every expression's operation order and grouping.
3. Vector math only through native/src/gd_math.h as its operation table allows (this plan adds the Vector3 rows, proven in Task 2); no std::max, std::min or std::clamp on floats.
4. Visit order is the GDScript's: ascending slot or id. A binary search over an ascending id array may replace a lookup only where it gives the same answer (the enemy read view answers exactly what EnemySystem.is_alive and position_of answered).
5. The mirror: write exactly the floats the GDScript wrote for an instance, in the same places (CrowdBatch.add_transform: three basis rows and the origin; add: the origin only; the colour when the batch has colours; the custom data); the floats past the count keep what earlier frames left, so the whole mirror, stale tail included, is byte-identical; a native fill starts from the batch's own setup mirror.
6. No FMA and no fast math (/fp:precise, -ffp-contract=off); only + - * / and sqrt; no time, no randomness, no engine singleton in native/src (delta and the clock come in as arguments); test_native_rules_guard enforces it.
7. Pins first: a GUT test pins the GDScript fill's mirror digests on deterministic frames, committed on its own while the GDScript runs; the native fill must pass it unchanged; a pin is never edited.
8. One implementation ships: when pins, goldens and the measured gain hold, the GDScript per-frame body is deleted; no runtime fallback.
9. Goldens: smoke 2599c7c2 (703 ticks), army f7a967ed (1353) and walls bfb05fc7 (1961) against tests/golden, full_idle 4385f569 (6911) twice, the gate digest e448ffdb with GATE_OK 300/300/0. The views only read, so nothing may move; any move stops the plan before the commit.
10. Every native method checks sizes, indices and slots that cross from GDScript and answers what the GDScript answered for bad input (a zero vector, -1, false, an unchanged mirror), never an out-of-bounds read.
11. GDScript names native classes as types (rule (i) of 04-14-SUMMARY).
12. Constants stay GDScript: every cap, colour, height, timing and arc number is handed to the native class at bind (configure); C++ holds no copy of a GDScript constant.
</exact_port_rules>

## Flagged Assumptions

- Spec-less edge probe (no 04-SPEC.md): BLDG-10 and ENMY-04 stay covered by the first-round `[edge ...]` truths of plans 04-01, 04-04, 04-06, 04-07 and 04-09 (this plan touches neither walls nor pathing); PLAT-01 is lifted as the budget truth of plan 04-28. Nothing is auto-resolved or dropped.
- Write shape (brief section 5.2, Claude's choice): the native class fills its own PackedFloat32Array copy of the batch mirror and GDScript hands it to the batch with commit_buffer (one `multimesh.buffer` assignment per batch per frame, as today), rather than C++ calling RenderingServer::multimesh_set_buffer on the batch's RID. Why: the CPU mirror stays the one readable truth for the tests, the pins and the stress frame counter (the headless renderer keeps no MultiMesh readback, RESEARCH F6); native/src stays free of RenderingServer and RIDs, inside the rules guard's arithmetic-only discipline; the price is one copy-on-write memcpy of at most 512 x 20 floats per batch per frame, a few microseconds. Rating: reversible.
- Alternative the owner did not choose: animating arrows on the GPU from origin, target and launch time (04-FRAME-REPORT.md's first candidate, paraphrased in the verifier's missing list) would remove the per-frame write entirely but changes the shader and the readable mirror; the owner's decision of 2026-10-20 is the C++ route, which this plan follows.
- Fixed targets: a building, castle or wall target re-resolves to the same point every frame (spot positions, the castle position and segment ends are constant map data), so the native ring keeps the launch target for them; the pins over the walls and army replays are the check.
- Unit targets are resolved in GDScript before the native fill (unit records are GDScript; the squad per-unit port was rejected by the owner); the stress night has none, so the cost there is one empty array per frame.
- The 3.0x bench bar is a conservative floor on a headless script-cost instrument (research F3 measured about 20x for packed fills); the real-window frame time is judged only in plan 04-28.
