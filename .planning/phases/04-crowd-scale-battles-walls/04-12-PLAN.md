Output: EnemyDef.drops_blocked_targets, the held-for-target memory and release rules in EnemySystem, StructureIndex.nearest_through_walls, three new test scripts, the migrated test_los_targets, and the amended docs.
</objective>

<decisions_settled_by_this_plan>
The diagnosis left three sub-rules open; this plan settles them (the owner's rule fixes the rest):
- (a) Visible targets still win. The structure choice of a default melee enemy is nearest_visible (radius 0, see b) first; only when it finds nothing does nearest_through_walls (nearest unit or building inside aggro_range by edge, walls ignored, the castle excluded) pick a target behind a wall. Reason: D-07 asks for smart enemies; chewing through a wall toward a target while one in reach stands beside you is not smart, and test_los_targets' "nearer unit behind loses to a farther one in sight" keeps holding for the default grunt. The king pull (priority 2) ignores walls for a default melee enemy: the king pulls through his own wall, as the owner listed the king among the targets.
- (b) The gap mouth: for a default melee enemy "behind a wall" means the centre line crosses a segment's solid: every line test of the new rule (the visible scan, the held-target test, the release test) uses radius 0.0, so a body line grazing the gap-edge segment within half_thickness + radius (balanced seed 2, night 8, enemy 187 at the north gap) counts as clear; the enemy walks the straight line and push_out slides it round the segment end. No per-target goal field is built for enemies (the goal-field budget belongs to squads and the bot king).
- (c) The castle: not one of the owner's listed targets and already covered by D-07, so the castle is never a target behind a wall. nearest_through_walls excludes it; for a default melee enemy a castle target is chosen and kept only while its centre line (radius 0, as in b) is clear, is dropped on a rescan when that line is blocked, and is never wall-taken (the held-castle wall take was dead code for melee and stays unreachable); the target-less castle march then keeps _aim_at_walls, _keeps_breaking, the hysteresis and wall_given_up exactly (owner, UAT test 9).
- Ranged (projectile_speed above 0) and flagged (drops_blocked_targets true) enemies keep every 04-06 gate with radius def.radius, unchanged.
- The flag is EnemyDef.drops_blocked_targets (default false, beside ignores_walls, documented as the Phase 6 hook). ignores_walls keeps precedence: an enemy that passes over walls never attacks one.
</decisions_settled_by_this_plan>
